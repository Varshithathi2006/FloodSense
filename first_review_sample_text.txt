[Shape: TextBox 1]
02 | Motivation & Problem Statement

[Shape: TextBox 2]
Problem: Current flood assessment systems are inadequate in two ways: text-based systems generate reports from secondary web sources without direct visual grounding, making them slow, incomplete, and unverifiable against actual site imagery; segmentation-only models identify flooded regions but leave severity interpretation and reporting to humans. No existing solution combines fine-grained flood segmentation with grounded, citation-traceable report production.

Scope: FloodSense is an end-to-end demo dashboard that includes automated flood-water segmentation from photos (benchmarking five CV approaches), RAG-based historical and protocol data retrieval, and structured severity reports created by LLM.

Objective 1: Go beyond binary flood detection by implementing 10-class flood/damage segmentation and benchmarking 5 CV techniques (Classical Thresholding, SAM, VLM, Grounding DINO+SAM2, SegFormer) with per-class F1 and IoU scores.

Objective 2: Create a RAG retrieval pipeline over a knowledge base of NDMA/FEMA flood protocols and historical flood records, targeting Precision@1 ≥ 0.90 and Recall@3 = 1.00.

Objective 3: Generate structured, grounded disaster SITREPs (severity assessment, impact estimation, action recommendations) traceable to segmentation output and retrieved protocol clauses.

Objective 4: Deliver a working end-to-end demo dashboard (image upload → structured SITREP report) suitable for lightweight field deployment.

03 | Consolidated Literature Review & Research Gap

[Shape: TextBox 2]
VLM-based Approaches:
• DisasTeller [1] — Multi-agent LVLM framework + RAG for post-disaster assessment (GPT-4o scored 7.3/10 on disaster grading)
• MASA + BLIP-2 [2] — Multi-atrous segmentation + LoRA-fine-tuned VLM captioning (80.77% BLEU score)

RAG-based Approaches:
• CrisiSense-RAG [3] — Multimodal RAG for Hurricane Harvey (reduced flood extent error by 8.62 pp)
• Training-free RAG [4] — Reinforced reasoning with 0.668 accuracy, 35.9–81.9x more cost-effective
• RS-RAG [5] — Cross-modal satellite retrieval-augmented VQA (79% classification accuracy)

Segmentation Approaches:
• Flood-DamageSense [6] — Mamba-based SAR multitask learning (F1 improvement of +19 pp)
• LLMArk [7] — Instance-aware 7B-parameter MLLM for flood risk (outperforms ChatGPT-4o)
• DisasterM3 [8] — 26,988 bi-temporal images, 9 disaster tasks, 40.8% referring segmentation improvement

Research Gap 1: Lack of robust multi-class flood segmentation — Most systems perform binary water/no-water segmentation without benchmarking across classical, foundation, and transformer-based approaches or differentiating flood water, debris, and damaged structures.

Research Gap 2: Lack of proper report generation — Systems either use standalone LLMs to generate unverifiable reports or output raw segmentation masks without interpretation. No existing work combines multi-model CV segmentation benchmarking with RAG-grounded, citation-traceable disaster report generation.

[Shape: TextBox 1]
04 | Finalized System Architecture & Methodology

[Shape: TextBox 2]
Three-Stage Pipeline Architecture:

Stage 1 — Multi-Class CV Segmentation (models_benchmark/)
  • 01_classical_thresholding.py: HSV/LAB color-space thresholding with morphological operations
  • 02_sam_segmentation.py: Meta SAM with automatic mask generator + class assignment heuristics
  • 03_visual_llm.py: Vision-Language Model (Gemini/GPT-4V) for semantic region parsing
  • 04_grounding_dino_sam2.py: Open-set detection (Grounding DINO) + SAM2 mask refinement
  • 05_segformer.py: HuggingFace SegFormer/OneFormer transformer-based semantic segmentation

Stage 2 — RAG Protocol Retrieval (rag_pipeline/)
  • vector_store.py: ChromaDB + sentence-transformers (all-MiniLM-L6-v2) over 4 knowledge-base docs
  • retriever.py: Dynamic query construction from CV damage metrics → semantic retrieval of NDMA/FEMA/NDRF protocols

Stage 3 — LLM Report Synthesis (report_generation/)
  • llm_engine.py: Grounded synthesis engine — CV features + RAG context → structured SITREP
  • prompt_templates.py: Domain-specific prompts for flood disaster reporting
  • export_utils.py: Multi-format export (JSON / Markdown / DOCX / PDF)
  • Deterministic fallback engine guarantees zero-hallucination with exact protocol citations

Deployment: Flask API (dashboard/server.py) → HTML/CSS/JS frontend → Render cloud (render.yaml, gunicorn)

[Shape: TextBox 1]
08 | Results Analysis & Interpretation

[Shape: TextBox 2]
Segmentation Analysis:
  • SegFormer/OneFormer achieves the best multi-class segmentation across all metrics — strong at flood-critical classes (Building-Flooded F1 = 1.0, Road-Flooded F1 = 0.95)
  • SAM excels at instance-level segmentation (Building-Flooded F1 = 0.85, Vehicle F1 = 0.40) but is 10x slower (1063 ms vs 95 ms)
  • Classical Thresholding is the fastest (10.5 ms) and performs competitively for Water (F1 = 0.21) and Grass (F1 = 0.45) — suitable as a real-time fallback
  • VLM and Grounding DINO + SAM2 underperform on pixel-level metrics — these are designed for region-level understanding, not dense segmentation
  • All models struggle with small/rare classes (Vehicle, Pool) — class imbalance in FloodNet is a known challenge

RAG Analysis:
  • MRR of 0.95 confirms the RAG pipeline consistently retrieves the most relevant protocol as the top result
  • Perfect Recall@3 (1.0) ensures all relevant protocols are within the top-3 results for every query
  • Dynamic query construction from CV damage metrics enables context-aware protocol retrieval (e.g., severity-specific NDMA evacuation triggers)

End-to-End Pipeline:
  • Complete image-to-SITREP pipeline operates in under 2 seconds (excluding LLM API latency)
  • Deterministic grounded synthesis engine guarantees zero hallucination and full protocol citation traceability

10 | Current Limitations & Technical Challenges

[Shape: TextBox 2]
Segmentation Limitations:
  • Multi-class mIoU remains moderate (best: 0.094) — FloodNet's severe class imbalance and small-object classes (Vehicle, Pool) are challenging
  • VLM and Grounding DINO + SAM2 produce region-level outputs not optimized for pixel-level metrics
  • Models were evaluated zero-shot / few-shot — fine-tuning SegFormer on FloodNet could significantly boost performance

RAG & Report Limitations:
  • Knowledge base limited to 4 curated documents — expanding to full NDMA/FEMA databases would improve coverage
  • Deterministic grounded synthesis is rule-based — API-connected LLM (Gemini/GPT-4) produces richer narrative but requires API keys
  • Report generation currently supports single-image analysis — batch/temporal analysis not yet implemented

Platform Limitations:
  • No live drone/satellite data ingestion — relies on pre-captured or uploaded imagery
  • GPU inference (SAM, SegFormer) is slow on CPU-only cloud deployments
  • Dashboard does not persist analysis history across sessions
